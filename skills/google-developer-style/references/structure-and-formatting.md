# Structure and formatting

Read this reference for structured documents, reports, guides, and editorial reviews.

## Headings

- Use sentence case and a logical hierarchy without skipped levels.
- Give every page one unique level-1 heading.
- Start task headings with a base-form verb: _Create an instance_.
- Use a noun phrase for a conceptual heading: _Instance migration_.
- Avoid starting headings with an `-ing` form when a clearer base verb or noun phrase works.
- Prefix optional sections with `Optional:`.
- Don't number headings to imply sequence, put links in headings, or use punctuation-heavy headings.
- Avoid code items in headings. If one is necessary, add a descriptive noun.
- Put content between a parent heading and its child heading; don't leave empty headings.

## Lists

- Don't create a list for one item.
- Introduce a list with a complete sentence unless the heading supplies enough context.
- Use a colon when the introduction immediately precedes the list. Use a period when material intervenes.
- Use numbered lists only when order, sequence, phase, or priority matters.
- Use bulleted lists for unordered items and description lists for term-description pairs.
- Keep structure, capitalization, and punctuation parallel.
- Capitalize list items. End complete thoughts and items with verbs in punctuation; omit punctuation for single words, verbless fragments, code-only items, links, or titles.
- If punctuation becomes inconsistent, rewrite for parallel structure or punctuate every item.
- Don't end a list with _etc._ or _and so on_. Introduce it as nonexhaustive instead.

## Tables

- Use a list for one value per item, a description list for pairs, and a table for three or more related fields.
- Don't use a one-column table, a table for page layout, or a table to arrange code.
- Avoid tables inside numbered procedures.
- Introduce every table with a complete sentence that states its purpose.
- Use concise, sentence-case headers without end punctuation.
- Mark row and column headers semantically. Don't merge cells.
- Don't use images, symbols, color, or formatting as the only way to convey table meaning.

## Links

- Add only links that help the reader complete the current task or understand the current concept.
- Provide a short definition or a couple of steps in place when a link would add unnecessary travel and cognitive load.
- Link to the most relevant page or heading. Avoid multiple links that serve the same purpose.
- Use short, unique, descriptive link text. Put the important words first.
- Don't use a bare URL, _click here_, _this article_, or _this document_ as link text.
- Keep punctuation outside link text.
- Explain unexpected behavior such as a download, email action, same-page jump, or forced new tab.
- Don't force a new tab unless necessary. If necessary, say so.

## Notices

- Prefer normal in-flow text unless the information benefits from interruption and visual distinction.
- Use a note for relevant but nonessential information that readers can skip and still succeed.
- Use a caution when the reader must proceed carefully.
- Use a warning for actions that can cause irreversible loss, financial harm, security exposure, or similar serious consequences.
- Put prerequisites, required steps, expected results, and essential success information in the main flow, not in notes.
- Avoid consecutive notices and notice overload.

## Numbers, dates, and units

- In English prose, spell out zero through nine and use numerals for 10 and greater.
- Use numerals for technical quantities, versions, measurements, percentages, prices, dimensions, ranges, decimals, and mathematical expressions.
- Spell out ordinal numbers in prose.
- Use a leading zero for a decimal less than one.
- Use a comma as the thousands separator in English and a period as the decimal point.
- Write dates as `Month D, YYYY`. If a numeric-only date is required, use `YYYY-MM-DD`.
- Write the date before the time. Avoid seasons for global content.
- Identify the time zone only when needed; prefer the UI's timestamp or a spelled-out region with its UTC offset.
- Use a nonbreaking space between a number and most units. Don't insert a space before `%` or between currency symbols and amounts.
- For a range with units, repeat the unit and use _to_, such as `10 MB to 20 MB`.
- Distinguish decimal storage units such as `GB` from binary units such as `GiB`.

## Punctuation and emphasis

- Use the serial comma.
- Prefer a period, comma, colon, or rewrite over a semicolon when practical.
- Use hyphens for compound modifiers only when needed for clarity; don't substitute an en dash for numeric ranges in Google style.
- Use parentheses sparingly. Move essential information into the sentence.
- Use bold for UI labels and run-in headings, italics for introduced terms or light emphasis, code font for technical literals, and underlining only for links.
