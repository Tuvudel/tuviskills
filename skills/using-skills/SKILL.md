# Using skills

Before acting on a non-trivial task, check whether a skill covers it. If one plausibly applies, open it and follow it. If none does, proceed normally. Do not load skills for trivial questions, small talk, or one-line edits.

Start from the entry skill for the kind of work. Each one is a short routing table that names the specialist skill to open:

| Work | Entry skill |
|---|---|
| Code: features, bugs, refactors, review, CI, shipping | coding-workflow |
| UI: layout, color, type, copy, accessibility, visual review | design-ui |
| Figures, diagrams, illustrations, charts | illustrate |
| Prose: docs, READMEs, PR text, specs, Hebrew content | docs-writing |

Rules:

- Re-check at a phase change (clarify → plan → build → verify → ship), after a resume, and after compaction.
- User and project instructions win over a skill. A skill wins over your defaults.
- Open only the skills the task needs. Carry their paths into delegated briefs instead of pasting their content.
- To create or edit a skill, use writing-skills.
